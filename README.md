# Lifetime в Rust: что это и зачем нужны явные аннотации

## Что такое lifetime

**Lifetime** (время жизни) — это **область видимости**, в течение которой **ссылка гарантированно валидна**. Компилятор **отслеживает** её, чтобы **не допустить** использования **висячих** ссылок.

**Ключевое:**

- **Каждая** ссылка имеет lifetime.
- Lifetime существует **только** на этапе **проверки типов**.
- В **рантайме** lifetime **нет** — это **абстракция компилятора**.
- Lifetime **не продлевает** жизнь данных — только **описывает** существующие отношения.

## Зачем нужны lifetime

### Проблема: висячие ссылки

```rust
fn main() {
    let r;
    {
        let x = 42;
        r = &x;   // ❌ x умрёт в конце блока
    }
    println!("{}", r);   // r указывает на мёртвую память
}
```

**Ошибка:**

```
error[E0597]: `x` does not live long enough
```

**Lifetime** помогает компилятору **поймать** это.

## Явные аннотации

### Синтаксис

```rust
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str { ... }
```

- **`'a`** — **имя** lifetime.
- **`&'a str`** — ссылка с lifetime `'a`.
- **`-> &'a str`** — возврат **живёт** не дольше `'a`.

### Читается как

> «Возвращаемая ссылка живёт **не дольше** пересечения **обоих** входных lifetime».

## Разбор примера `longest`

```rust
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() >= b.len() {
        a
    } else {
        b
    }
}

fn main() {
    let s1 = String::from("abc");
    let s2 = "fehg";

    let res = longest(s1.as_str(), s2);
    println!("{}", res);   // fehg
}
```

### Что происходит

1. **`s1`** — `String`, живёт **до конца** `main`.
2. **`s2`** — `&'static str`, живёт **всю** программу.
3. **`longest`** — возвращает ссылку **с минимальным** lifetime.
4. **`'a`** = **минимум** из двух lifetime.
5. **`res`** живёт **не дольше** `'a` — **безопасно**.

### Почему аннотация **обязательна**

```rust
// ❌ Без 'a — ошибка
fn longest(a: &str, b: &str) -> &str { ... }
```

**Ошибка:**

```
error[E0106]: missing lifetime specifier
  |
1 | fn longest(a: &str, b: &str) -> &str {
  |            ----     ----     ^ expected named lifetime parameter
  |
  = help: this function's return type contains a borrowed value,
          but the signature does not say whether it is borrowed from `a` or `b`
```

**Компилятор не знает**, от **какого** из двух аргументов **зависит** возврат.

## Lifetime в структурах

```rust
#[derive(Debug)]
struct Parser<'a> {
    input: &'a str,
    pos: usize,
}

fn main() {
    let v = Parser {
        input: "abc",
        pos: 10,
    };
    println!("{:?}", v);   // Parser { input: "abc", pos: 10 }
}
```

- **`'a`** — **lifetime** ссылки `input`.
- **`Parser`** **не переживёт** `input`.
- **`'static`** для `"abc"` — **всё ок**.

## Elision (пропуск) lifetime

**Компилятор** может **сам** вывести lifetime в **простых** случаях.

### Правило 1: каждый аргумент — свой lifetime

```rust
fn foo(a: &str, b: &str) -> &str { ... }
```

**Компилятор** видит:

```rust
fn foo<'a, 'b>(a: &'a str, b: &'b str) -> &? str
```

### Правило 2: если **один** входной lifetime — возврат его

```rust
fn foo(a: &str) -> &str { ... }
```

**Компилятор** видит:

```rust
fn foo<'a>(a: &'a str) -> &'a str { ... }
```

**Аннотация не нужна** — **один** входной, **один** выходной.

### Правило 3: `&self` — возврат его lifetime

```rust
struct Foo;

impl Foo {
    fn method(&self) -> &str { ... }
}
```

**Компилятор** видит:

```rust
fn method<'a>(&'a self) -> &'a str { ... }
```

### Когда elision **не** работает

```rust
fn longest(a: &str, b: &str) -> &str { ... }
```

- **Два** входных lifetime.
- Компилятор **не знает**, **какой** из них вернуть.
- **Нужна** явная аннотация.

## Правило большого пальца

| Ситуация | Аннотация? |
|---|---|
| **Одна** входная ссылка → одна выходная | ❌ Не нужна |
| **Несколько** входных → выходная ссылка | ✅ **Обязательна** |
| **`&self`** → выходная ссылка | ❌ Не нужна |
| **Нет** ссылок на входе → выходная ссылка | ❌ Не нужна (или `'static`) |

## Аннотация **не продлевает** жизнь

```rust
fn foo<'a>(x: &'a str) -> &'a str {
    x
}

fn main() {
    let s = String::from("hello");
    let r = foo(&s);
    println!("{}", r);
}
```

**`'a`** — **не** «продлевает» `s`. Это **описание** — «возврат живёт **столько же**, сколько вход».

## `'static`

**`'static`** — **особый** lifetime: **вся** программа.

```rust
let s: &'static str = "hello";   // строковый литерал
```

**Строковые литералы** — **`'static`** (в **бинарнике**).

### `Box::leak`

```rust
let s: &'static str = Box::leak(String::from("hello").into_boxed_str());
```

**Утечка** памяти → `'static`.

## Сводная таблица

| Ситуация | Что делать |
|---|---|
| **1 вход → 1 выход** | Elision |
| **N входов → 1 выход** | Явная `'a` |
| **`&self` → выход** | Elision |
| **`'static`** | Вся программа |
| **Структура со ссылкой** | `'a` в определении |

## Сводная таблица

| Аспект | Описание |
|---|---|
| **Lifetime** | Область валидности ссылки |
| **В рантайме** | ❌ Нет |
| **В типах** | ✅ `'a` |
| **Elision** | Автовывод |
| **Явная** | Когда N входов |
| **`'static`** | Вся программа |

## Итог

- **Lifetime** — **область** валидности ссылки.
- **Существует** только на этапе **проверки типов**.
- **Явные аннотации** — когда компилятор **не может** вывести.
- **Самый частый случай:** функция возвращает ссылку, **несколько** входных ссылок.
- **Elision** работает для **1 вход → 1 выход** и `&self`.
- **`'static`** — вся программа.
- **Аннотация не продлевает** жизнь — только **описывает**.
- **В вашем примере:**
  - `longest<'a>` — **обязательна** (2 входа);
  - `Parser<'a>` — **обязательна** (структура держит ссылку).
- **Правило:** если **несколько** входных ссылок и **возврат** — **ссылка**, аннотация **почти всегда** обязательна.
